## Section 7: Failure Analysis

The campaign had no terminal failure, but three recoverable failure signatures are relevant.

### 7.1 Cross-platform `pwsh` resolution defect

**Observed in:** [#4](https://github.com/edburns/dd-3068633-win32-x64-04/pull/4)  
**Evidence:** Initial acceptance output reported `Tests Passed: 3, Failed: 1`. The failure occurred because `Get-Command pwsh` returned multiple application paths that were coerced into one invalid executable string.  
**Root cause:** The isolated CLI test assumed a single command-resolution result across environments.  
**Resolution:** CCA selected exactly one resolved application before launching the child process. The repository acceptance command then passed 4/4 tests locally and in two CI jobs.  
**Impact:** One remediation cycle and several minutes of stage-30 time; no escaped defect.

### 7.2 Check-publication race

**Observed in:** [#4](https://github.com/edburns/dd-3068633-win32-x64-04/pull/4) after remediation.  
**Evidence:** `gh pr checks` briefly returned `no checks reported` immediately after the new SHA was published.  
**Root cause:** The helper treated temporary absence of current-HEAD check runs as an immediate failure instead of a not-yet-materialized state.  
**Resolution:** Shepherd waited for SHA-bound checks to appear, then required their successful completion.  
**Impact:** No correctness impact; avoidable orchestration delay and a misleading failure-shaped log entry.

### 7.3 Brittle scoped-file comparison

**Observed in:** [#5](https://github.com/edburns/dd-3068633-win32-x64-04/pull/5) stage 30.  
**Evidence:** The first atomic gate threw `SHEPHERD FAILED: scoped-files requirement changed`, while the repeated gate verified the same two expected files and unchanged HEAD.  
**Root cause:** A joined-string equality check made file-set validation order-sensitive or formatting-sensitive.  
**Resolution:** The repeated gate checked count and explicit membership for both expected paths.  
**Impact:** Approximately 26 seconds; no product change or additional CCA cycle.

One additional diagnostic command combined incompatible `gh pr view --comments` and `--json` flags during [#4](https://github.com/edburns/dd-3068633-win32-x64-04/pull/4) inspection. A corrected query immediately recovered. No timeout, stuck poll, review refusal, unresolved thread, or manual code intervention occurred.

## Section 8: Observations and Recommendations

### 8.1 What worked well

- The serial dependency was enforced: the factorial task began only after the Fibonacci PR merged.
- Repository-owned tests and SHA-bound CI caught a real cross-platform defect before readiness.
- CCA responded successfully to a precise remediation request in one cycle.
- Current-HEAD review identity, check state, base branch, unresolved-thread count, and mergeability were revalidated immediately before each merge.
- Both CCRA reviews converged in one round with zero findings.
- The run manifest provides a reproducible campaign boundary and confirms `lessonPropagation: off`.

### 8.2 What did not work well

- The workflow helper surfaced a transient lack of check runs as a failure instead of polling for publication.
- Scoped-file validation used brittle string comparison before falling back to a correct set-membership check.
- One `gh pr view` diagnostic used mutually exclusive flags.
- Token observability is incomplete: the JSONL logs expose AIU and premium requests but no input/output token fields.
- No parent `*memory*.md`, `*prompts.md`, or `*job-logs.txt` artifacts were present, limiting correlation beyond the four captured CLI sessions.

### 8.3 Recommendations

1. **Poll for check creation before watching completion.** Treat zero checks on a newly published SHA as a bounded pending state, then fail clearly only after a publication timeout.
2. **Use order-independent path-set validation everywhere.** Compare normalized sets and counts rather than joined strings.
3. **Add command-level tests for GitHub CLI argument combinations.** This would catch invalid combinations such as `gh pr view --comments --json` before campaign execution.
4. **Preserve the targeted CCA remediation pattern.** The failure report for [#4](https://github.com/edburns/dd-3068633-win32-x64-04/pull/4) named the exact file, failure mode, required invariant, and acceptance command; CCA converged in one cycle.
5. **Emit stable aggregate telemetry.** Include per-session input tokens, output tokens, cache tokens, AIU interpretation/version, review rounds, and comment counts in a compact run summary so post-mortems do not need to infer metrics from presentation logs.
6. **Retain strict current-HEAD gates.** Review acknowledgement, review commit identity, SHA-bound checks, thread resolution, and a final HEAD reread materially reduced race risk without harming throughput in this small campaign.
7. **Use this run as the control baseline.** Compare future `lessonPropagation: campaign` runs against the 30m47s wall time, one CCA remediation, two CCRA rounds, zero CCRA comments, and 210.802120 reported AIU, while accounting for task equivalence.
